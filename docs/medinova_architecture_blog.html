MediNova
Agentic Healthcare

Un Concierge orchestre quatre spécialistes via A2A. Chaque spécialiste accède à des capacités métier via MCP. Les tools choisissent le backend adapté : SQL pour les faits structurés, Hybrid RAG pour les documents, API lorsque la donnée doit être interrogée à la source.

02. Concierge Agent

Le Concierge est le point d’entrée. Il comprend l’intention, décompose une demande multi-domaines, sélectionne un ou plusieurs spécialistes, délègue via A2A puis synthétise leurs résultats.

Il fait

Orchestration

Intent detection, routing, décomposition, appels A2A, agrégation et réponse finale.

Il ne fait pas

Accès Data

Pas d’accès direct à PostgreSQL ou Qdrant, pas de RAG médical direct, pas d’invention lorsqu’un spécialiste ne retourne pas l’information.

03. Les quatre Specialist Agents

Agent 01

💊 Medication Agent

Objectif. Répondre aux questions sur l’identité d’un médicament, ses informations médicales, ses interactions et ses données de coût en s’appuyant sur la source et le backend adaptés.

get_medication()

Identité, substance, dosage, forme, ATC, composants.

→ SQL
search_medical_info()

Indications, précautions, contre-indications, effets indésirables, monographies.

→ Hybrid RAG
check_interactions()

Interaction exacte puis contexte documentaire si nécessaire.

→ SQL + RAG
get_cost_info()

Présentation, prix et données de remboursement disponibles.

→ SQL / API

Agent 02

💉 Vaccination Agent

Objectif. Répondre aux questions portant sur le calendrier vaccinal et les informations/recommandations vaccinales intégrées.

get_schedule()

Interrogation déterministe du calendrier structuré.

→ SQL
search_vaccine_info()

Recherche de passages documentaires pertinents.

→ Hybrid RAG

Agent 03

🧪 Biology Agent

Objectif. Exploiter les données Bioreco : recommandations de biologie médicale, bilans types et actes NABM.

search_reco()

Recommandations documentaires.

→ Hybrid RAG
get_lab_panel()

Bilans types structurés.

→ SQL
get_NABM_act()

Actes NABM structurés.

→ SQL

Agent 04

🩺 Medical Recommendations Agent

Objectif. Répondre aux questions portant sur les recommandations officielles de prise en charge, diagnostic, prévention et bonnes pratiques intégrées depuis la HAS.

search_recommendations()

Recherche hybride dans les sections de recommandations HAS avec conservation de la provenance.

→ Hybrid RAG

04. MCP & design des Tools

MCP n’est ni une base de données ni un moteur de recherche. Il expose à chaque spécialiste les capacités métier qu’il peut appeler.

Specialist Agent
       │
       │ MCP
       ▼
┌────────────────────┐
│ Domain MCP Server  │
├────────────────────┤
│ business_tool_A()  │ ─────→ backend adapté
│ business_tool_B()  │ ─────→ backend adapté
│ business_tool_C()  │ ─────→ backend adapté
└────────────────────┘

On privilégie quelques tools métier cohérents plutôt qu’une multitude de micro-tools. Chaque résultat doit transporter sa provenance : source, identifiant, URL si disponible, version/date et timestamp de récupération.

08. Provenance, sécurité & observabilité

Provenance

Chaque résultat conserve autant que possible source, source_id, document/section, URL, version, date de mise à jour et date de récupération.

Garde-fous

Information médicale ≠ décision clinique. Un résultat absent ne devient jamais une affirmation. Une synthèse générée n’est pas présentée comme une source.

Data observability

Runs Prefect, documents chargés, changements, erreurs de normalisation, embeddings, indexation et latence.

Agentic observability

Routing, appels A2A, appels MCP, échecs tools, sources récupérées, empty retrievals et latence end-to-end.

Règles d’architecture à retenir

Dataset ≠ Agent

Un agent représente une capacité/domaine métier, pas une source.

Tool = capacité métier

Pas de prolifération de micro-tools techniques.

Backend selon le besoin

Fait structuré → SQL. Document → RAG. Donnée dynamique → API si nécessaire.

Provenance first

Une information importante doit rester rattachable à sa source.

Architecture finale : User → Concierge → A2A → Specialist Agent → MCP → Business Tool → SQL / Hybrid RAG / API → source médicale.
